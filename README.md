# tzledger

**Fail-closed timezone loader for time-series corpora — every read leaves an audit record.**

時間序列的強制載入層。讀進來的 `ts` 欄保證是 tz-aware UTC；判不出時區的檔**直接拒絕載入**；每一次載入都留下可稽核的紀錄。

## 起因

一支資料擷取腳本裡有一行 `+ Timedelta(hours=8)`。

它污染了 **90 個資料檔**，那些檔又餵給了下游分析，最後影響 **44 個已經寫成結論的研究結果**。從寫下那行到發現，中間隔了好幾個月。

問題不在那一行寫錯了。問題在於**它錯得毫無跡象**：

- 程式沒有壞掉，沒有例外，沒有紅字
- 資料的型別、長度、欄位、單調性全部正常
- 畫出來的圖看起來完全合理
- 每一個既有的檢查都通過了

時區污染不會讓結果變成明顯的垃圾，只會讓它**安靜地偏移**。而偏移過的結果，與正確的結果長得一模一樣。

所以修法不是去改那支腳本。是**取消「可以直接 `read_csv` 讀時間序列」這件事**。

## 30 秒看懂

```python
from tzledger import Loader, LoaderConfig, UnresolvedTimezone

loader = Loader(LoaderConfig(root='data', manifests=['data/tz_manifest.json']))

df = loader.read_ts('data/AAA_1min_2023.csv', usecols=['close'])
df['ts'].dt.tz          # → UTC，永遠是 UTC

loader.read_ts('data/UNKNOWN_1min_2023.csv')
# UnresolvedTimezone: fail-closed:「UNKNOWN_1min_2023.csv」無時區判定
#   放行會產生「一半修正過、一半沒有」的資料 —— 那比全錯更難發現，
#   因為錯誤只出現在接縫處，而接縫在圖上看起來像正常的波動。
```

跑一遍完整流程（不需要任何外部資料，會自己生一份小語料）：

```bash
pip install -e ".[dev]"
python examples/demo.py
pytest
```

## 四個設計決定

### 1. 沒有全域開關 —— 修正永遠生效

前一版工具的預設是**關閉**的，要設 `TZ_FIX=1` 才會修正。

結果是：「忘記設環境變數」與「這批資料本來就乾淨」在輸出上**完全無法區分**。兩種情況都給你一份看起來正常的 DataFrame。

安全機制的預設值如果是關的，它就不是安全機制，是一個選項。

### 2. 宣告式，不做算術

```python
# ✗ 對數字的操作
t = t - pd.Timedelta(hours=8)

# ✓ 對意圖的宣告
t = t.dt.tz_localize('Asia/Taipei').dt.tz_convert('UTC')
```

**先講一個對自己不利的事實**：在台北，這兩種寫法的數值**完全相同**。台灣自 1980 年起沒有日光節約，偏移量恆為 +8。所以只用台北的資料，寫不出任何一個能區分兩者的測試。

差別在三個地方：

| | 算術 `- 8h` | 宣告式 |
|---|---|---|
| **有 DST 的時區** | 轉換日之後整段錯一小時 | 正確 |
| **冪等性** | 套兩次 = 位移 16 小時 | 套幾次都一樣 |
| **輸出帶不帶資訊** | tz-naive，看不出修過沒 | tz-aware，資料自己說得出來 |

DST 那一條是可驗證的，所以做成了測試（[`tests/test_dst.py`](tests/test_dst.py)）：一段橫跨美東 2023-03-12 轉換點的資料，固定加 5 小時會在轉換點裂開一道**一小時的接縫**，而且只錯後半段。

冪等那一條的實際後果：前一版工具因為輸出 tz-naive，資料**帶不出「我修過了」這個資訊**，於是與別的工具疊加時再修一次 —— 與正確資料的逐點相等率掉到 **2–8%**，價格差到四位數，**全程沒有任何錯誤訊息**。

### 3. 假警報也是一種失效

第一版把「未登錄判定表」與「有時區風險」混為一談。305 個語料檔裡有 **100 個**觸發 fail-closed —— 但其中 **84 個**（自帶時區 35 個 + epoch 49 個）本來就沒有歧義。

被無謂地擋了 84 次之後，使用者唯一理性的反應就是去找放行開關，然後那個開關會一直開著。

所以 `sniff_format()` 先看**檔案自己說了什麼**：帶 `+00:00` 或 `Z` 的、數值 epoch 的，本質無歧義，不需要查判定表。只有裸字串才真的有歧義。

**安全機制的可用性是它的安全性的一部分。**

### 4. 判定與載入分開

判定「這個檔的原始時間戳在哪個時區」需要人看證據 —— 比對已知無歧義的來源、逐點檢查、看跨相關的峰值落在哪。載入需要能無人值守地跑。

塞進同一個函式，結果一定是載入去猜判定，而猜錯不會有人知道。

所以這一層**只查表，查不到就拒絕**。判定是外部事實紀錄（一份 JSON），由一次性的鑑定作業產出。

## 兩個延伸機制

### 跨序列覆蓋率 —— 抓「每個檔都對，但少載了一半」

一組腳本用精確檔名樣式 `{symbol}_1min_{year}.csv` 逐年讀取。其中一個標的在磁碟上是**半年一檔**，於是那個樣式只命中 6 年裡的 2 年。

聚合成小時 bar 後只有 **12,341** 根，其餘標的 39,000–45,000 根。**那個數字一直印在畫面上，沒有人拿它跟別的標的比。**

每一項檢查都通過了。缺的不是檢查，是**比較的對象**。

判準本身也踩過一次坑：第一版用「列數 ÷ 中位列數」，結果誤報了一個上市較晚的標的 —— 它只有 2.93 年歷史，列數比值 0.579，但那是**合法的**。改看**密度 = 列數 ÷ 年數**：

| | 列數比值 | 密度 |
|---|---|---|
| 漏檔（12,341 根 / 5.41 年，同儕約 42,000 根） | 0.29 → 抓到 | **0.26** → 抓到 |
| 上市較晚（2.93 年，但每年 526,648 列） | 0.579 → **誤報** | **1.002** → 正確 |

兩種判準都抓得到漏檔。差別在第二列：列數比值的代價是**把合法的短歷史一起報成問題**，而假警報會逼人去調參數繞過檢查 —— 又回到第 3 節那個問題。

「資料比較少」與「資料漏了」是兩件事，用總量分不出來。

### 結論身分 —— 同一份資料，可信度取決於你怎麼用它

修好之後的問題是：**之前的結論，哪些真的被影響到了？**

全部作廢，成本高到不會有人真的去做；全部保留，那修它幹嘛。

把同一份資料的修正前後拿來比對：

- **依位置比對（第 n 列對第 n 列）**：相關係數 **1.0000**，完全相同
- **依時間戳聚合成日線後比報酬**：相關係數只有 **0.535 – 0.612**

同一份資料，兩種讀法，一個毫髮無傷，一個面目全非。

原因：位移不改變任何一列的**內容**，但會改變「哪些列屬於同一天」。所以缺陷只透過三條路徑傳導 —— 日/週界線、跨來源對齊、日曆時段判斷。沒走這三條路的分析（純單一來源、順序式）**不受影響，結論可以留**。

因此 `classify()` 要求呼叫端**顯式聲明**有沒有走這些路徑。這個參數沒有預設值：本模組知道你讀了什麼，但無法知道你怎麼用；給預設值等於替使用者猜，而猜錯的方向是「以為結論還有效」。

## 測試

68 個測試，全部用合成資料，`git clone` 之後直接跑。

原型版本的測試綁死在作者機器上的絕對路徑，**只有一台機器跑得動** —— 等同沒有測試。合成資料同時解決另一個問題：真實語料裡沒有「壞掉的時間戳」這種樣本，所以用真實資料寫不出 NaT 的測試，而那正是最需要被測的分支。

### 測試有沒有牙齒

「全部通過」本身不是證據 —— 一個什麼都不檢查的測試集也會全部通過。所以刻意把程式改壞，看測試抓不抓得到：

| 注入的缺陷 | 抓到 |
|---|---|
| 宣告式轉換 → 固定偏移量算術 | 3 個失敗 |
| 拿掉 fail-closed（`BAD_VERDICTS` 清空） | 11 個失敗 |
| 空 ledger 回傳 `CLEAN`（還原成 fail-open） | 2 個失敗 |
| 密度判準 → 列數比值 | 2 個失敗 |
| 黑名單失效 | 2 個失敗 |
| NaT 檢查失效 | 2 個失敗 |
| 相容層不再冪等（已 aware 的資料重新 localize） | 1 個失敗 |

第一項一開始**沒有被抓到**。當時的測試語料只有台北時間，而台北沒有日光節約 —— 兩種寫法的數值完全相同，測試分不出來是合理的。

但這代表 README 上面那句「宣告式比較好」，在補測試之前是**沒有證據的**。補上 `tests/test_dst.py` 之後才立得住。

### 一個由 demo 掉出來的 bug

寫 `examples/demo.py` 跑完整流程時，覆蓋率檢查把三個一模一樣的序列全部標成離群。

原因是我在算密度前卡了一個「跨度要大於 0.1 年」的門檻防除以零 —— 結果**跨度不足五週的序列全部算不出密度，於是全部觸發警報**。一個為了安全設的保險，自己變成了假警報的來源，正好是第 3 節講的那種失效。

已修（只在跨度為零時放棄計算），並補上迴歸測試。

## 這個 repo 不包含什麼

誠實劃界：

- **不含任何真實資料。** 測試與 demo 的語料都是現生的。
- **不含判定工具。** 「這個檔是哪個時區」的鑑定作業是另一件事，需要人看證據，不在這一層。
- **不含策略、回測、交易邏輯。** 那些是這一層的**使用者**，不是它的一部分。
- **`compat.install()` 是過渡工具。** monkeypatch `pd.read_csv` 有代價：一行 `read_csv` 做了什麼，變成取決於別處有沒有呼叫過 `install()`。接受這個代價，是因為替代方案（先改寫幾十支腳本才能開始重跑）在實務上的結果是兩件事都不做。新程式請直接用 `Loader.read_ts`。

## 由來

這是一套個人量化研究系統裡資料載入層的**公開整理版**。原型是單一檔案 649 行，含硬編路徑與該系統特有的語料格式，只在一台機器上跑得動。

整理成公開版時做的事：路徑與判定表改為注入、移除全域可變狀態（原型用模組層 list 當 ledger，測試之間會互相污染）、把綁死絕對路徑的測試改寫成合成語料、補上 DST 案例與迴歸測試、加 CI。

原系統本身不開源。
